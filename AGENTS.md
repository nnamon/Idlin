# Idlin 2.0 working agreement

Idlin 2.0 is being designed from first principles.

- Treat the pre-2.0 archive as reference material, never as an inherited design.
- During discovery, preserve the author's language and uncertainty. Record rough
  ideas in `docs/inbox.md` before trying to reconcile or formalize them.
- Keep product requirements separate from implementation choices.
- Mark assumptions and unresolved questions explicitly.
- Promote a requirement only when it is specific enough to accept or reject.
- Record consequential, difficult-to-reverse choices in `docs/decisions/` with the
  context, alternatives, decision, and consequences.
- Do not begin implementation or select a technology stack until the direction and
  first build slice have been explicitly chosen.
- Do not copy old code or architecture by default. Any reuse needs a current 2.0
  reason.
