# 0013: Agents post their work on the issue and the pull request

Date: 2026-11-27. The operator on #267: "incorporate more of the github
collaboration features into the swarm process please. For example, different
agents could post and read from issues, reviewers can leave comments and
suggested changes inline on prs, this would make the game dev process more
like a real team and give insight into the goings on." Changes section 4 and
section 8 of `AGENTS.md`, steps 2, 4 to 7 and 9 of `process/cycle.md` and a new
section before step 0, `docs/watch-rubric.md`, and step 3
of `process/daily.md`.

| Decision                                                                                                                                                                                     | Rejected alternative                                                                  | Why                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Builders read the issue's comments before starting, and comment when they start, when they decide something worth knowing, and when the pull request is up.                                  | Builders report only to the conductor's thread.                                       | The issue then holds the whole story of a change, and the operator can follow it without opening each thread.                                           |
| Reviewers post a GitHub review: a summary plus inline comments, with `suggestion` blocks for small fixes. The event is `COMMENT`, and the summary's last line says MERGE-OK or DO-NOT-MERGE. | The reviewer returns its findings to the conductor, who restates them in one comment. | Inline comments sit on the line they are about. All agents post as one account and GitHub refuses approve or request-changes on one's own pull request. |
| The builder fixing findings replies to each inline comment and resolves the thread. The conductor's triage comment links to the review.                                                      | The conductor's triage comment as the only record of what happened to each finding.   | Each finding's outcome is next to the finding, and the open threads show what is still unanswered.                                                      |
| The watch judge posts its own verdict on the pull request.                                                                                                                                   | The conductor posts the judge's verdict.                                              | One less hand-off, and the verdict is in the judge's own words.                                                                                         |
| Issues are tracked on the project board with a Status and an Area. Builders move their issue to In progress and In review; the conductor adds issues and sets Blocked and Done.              | Labels alone.                                                                         | The board shows at a glance what each builder is on and what waits on review.                                                                           |
| The daily digest checks the last run of the `capture` workflow on `main`, both its jobs, and the conductor files a `bug` for each failure.                                                   | Leaving the `main`-only runs to whoever notices.                                      | That workflow is not required, so a failure there blocked nothing and nobody was named to look at it.                                                   |
